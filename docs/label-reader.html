Steps 1 to 3

Label reader (transcription, structuring and error checking)

Three web pages that read your label pictures, sort the text into columns, and help you check the result.

There is nothing to install. You open a file in your browser, drop in your pictures or spreadsheet, and paste in a key for the AI service you want to use. Each page hands its result to the next as a spreadsheet (CSV file).

Open the pages

  1. Download editha

    Download the ZIP file and unzip it. Open the folder museum-label-reader.

  2. Double-click a page

    It opens in your web browser.

    StepFilePage title
    11-transcribe-ocr-V.3.0.htmlMuseum label OCR
    22-data-structuring-V.3.0.htmlMuseum label structuring
    33-manual-checks-reruns-V.4.0.htmlMulti-parsing and manual corrections

Keep each page open in its own browser tab, or open them one at a time. Your work in each page is kept in the browser, so closing a tab does not lose paid work.

Get a key for an AI service (API key)

The pages read pictures using an AI model from OpenAI (GPT) or Anthropic (Claude). You need an account with at least one of them, and a key for it. The key is a long piece of text that lets the page use your account. The company bills your account for each picture read.

  • OpenAI: create a key at platform.openai.com/api-keys.
  • Anthropic: create a key in the Anthropic Console.
Treat the key like a password

Anyone who has it can spend your money. The page sends it only to the company that issued it. Tick Remember on this computer only on a computer that is yours. Set a monthly spending limit in your account.

You choose the model on each page. Model names starting with claude go to Anthropic, and all others go to OpenAI. Custom… lets you type any other model name your key can use. It has to be able to read images. The page records which model actually answered for every reading.

Things every page has

Simplified mode
Hides the advanced options so you see only the essentials. Nothing is deleted and your settings are kept. Switch it off to get them all back.
The ? bubbles
Click or hover over one for a plain explanation of that setting.
Labels to read
All of them, or only the first N, or a random N. You can count single labels or whole specimens. A random sample takes a seed number, so you can pick the same sample again. Always try 10 first.
Requests at once
How many pictures are sent at the same time (parallel requests). It only changes the speed. Lower it if you see rate-limit errors.
Use the Batch API
OpenAI models only. Sends the labels as one job at half the price, with results within 24 hours. You can close the page and come back.
Stop
Stops sending and cancels the readings in progress. What has finished is kept.
Save and Export run info
Export run info writes a plain text file with counts, tokens used, every setting and the full instructions sent to the AI. It is meant for a methods section.
Start over
Asks first. You can clear everything, or only reset the token counts. Download what you still need before you clear anything.

Step 1 · Type up the text (transcription, OCR)

Page: 1-transcribe-ocr-V.3.0.html. Input: a folder of label pictures. Output: a spreadsheet with the columns Specimen.image, Image.name, Segments and Model.

The model is asked for an exact transcription (diplomatic transcription): write what is there, with no correcting or tidying. Words it cannot be sure of are marked [?] and unreadable ones [illegible].

  1. Model and key

    Choose a model and paste your key. For handwriting, set Image detail to high (OpenAI models only).

  2. Images

    Drop the folder of label pictures onto the page, or use Choose folder or Choose images. If you used the label finder, this is the 04_cropping_result folder.

    Optionally prepare the pictures first (preprocessing): Upscale factor enlarges them before sending, which can help with small writing, and Autocontrast makes faded ink stand out. Left alone, pictures are sent unchanged.

  3. Labels to read

    Choose all, or a small first or random batch to test. See above.

  4. Write your instructions (the prompt)

    Click Open editor. The page has a fixed part that always asks for an exact transcription returned in a set format. You add guidance about your labels.

    • Let AI help write it: describe your labels (the collection, the kinds of label, languages, handwriting or print, how dates are written) and click Write prompt. Read the suggestion, then Use this prompt. A stronger model costs very little here, because writing the prompt is one short request.
    • Check it: Check for contradictions asks a model to point out instructions that conflict with each other.
    • Or write it yourself: edit the text directly, and Save to keep it. You can also load a .txt file or download yours.

  5. Click Transcribe

    Each label appears next to its transcription. The page counts how many are transcribed, how many have [?] or [illegible] in them, how many failed and how many are waiting. A reply that is not in the expected format counts as failed.

    Use the arrows to browse. Re-transcribe sends again all of them, the ones you selected, the uncertain ones, or the failed ones. That is a new paid request each time.

  6. Save

    Save CSV gives you the spreadsheet for step 2. You can also save the raw replies from the AI, as a zip, and the run info.

Step 2 · Sort the text into columns (data structuring)

Page: 2-data-structuring-V.3.0.html. Input: the spreadsheet from step 1. Output: a spreadsheet with one column per fact you chose, plus a Tags column listing which facts each label contained.

  1. Model and key, and the spreadsheet

    Same model, key, requests-at-once and batch options as step 1. Drop the step 1 spreadsheet onto OCR results, and choose how many labels to do. Try 10 first.

  2. Pick the fields (Darwin Core fields)

    Choose what you want extracted, such as eventDate, verbatimEventDate, locality or recordedBy, and click Add. These are the standard column names for biodiversity data.

  3. Write the instructions

    Click Open editor.

    • Write with AI: describe your labels if you like, add a note for any field, and click Write prompt from fields.
    • Change with an instruction: type what you want changed in plain words, then click Suggest changes.
    • Check for contradictions before you run.

    If you change the fields later, the page warns you that the instructions may need updating.

  4. Click Run Structuring

    You see each label's text next to the fields that were filled in. Use Prev and Next to browse.

  5. Save

    Save CSV gives you one row per label, ready for step 3. Export run info records the settings.

Step 3 · Check the work (manual checks and re-reads)

Page: 3-manual-checks-reruns-V.4.0.html. Input: the spreadsheet from step 2 and the folder of label pictures. Optionally, the photos of the whole specimens. Output: a corrected spreadsheet and the evidence for how reliable the readings were.

Why check?

An AI model can read a label wrongly with complete confidence. This step lets you find out how often, for your collection, and fix the mistakes.

  1. Load the spreadsheet and tell the page what each column is

    Drop in the step 2 spreadsheet (the parse-1 CSV). Then say which column holds the label picture name, the specimen, the tags and the transcription. A picture name is normally Image.name.

  2. Load the pictures

    Drop the folder of label pictures. If you have photos of the whole specimens, drop them too. They are shown next to the label while you check, and are never sent to the AI.

  3. Choose the columns to check

    The list comes from the Tags column, with how many labels have each. These are the values you will check, and the only ones the AI is asked to read again.

  4. Check by hand (manual checks, "P1")

    Go through the first reading against the picture. It is built for the keyboard.

    KeyMeaning
    ← →Previous and next
    SpaceRight
    XWrong
    CUnsure
    ZGo back
    ?Show this list of keys

    Filters and a search box help you find a particular label or kind of value.

  5. Get a second opinion (parse 2)

    Choose a model and key, choose how many labels, and click Run parse 2. The AI reads the picture again, one question per label and column, without seeing the first answer. Each value is then compared with the first reading:

    • AGREE or DISAGREE. Text must match after trimming spaces.
    • Dates are compared as dates, with a third result, COMPATIBLE. The page asks you whether dates on your labels are day first or month first, because 03/04 means different things.

    You can add notes for a column and read the exact final instructions before anything is sent. Check for contradictions works here too.

  6. Test the agreements (parse 3)

    Click Run parse 3. It reads again only the values where the first two readings agreed, and records whether the agreement held. A value that flips between readings is a warning sign.

  7. Say which value is right

    For each compared value, choose the right reading.

    KeyMarkUse when
    1P1The first reading was right
    2P2The second reading was right
    3P3The third reading was right
    SpaceBothBoth readings were right
    XNeitherBoth were wrong. You will type the right value.
    CUnsureYou cannot tell from the picture

    Click Correct to type the right value for each one you marked Neither. The box starts with the closest reading. Press Enter to accept and move to the next. Leave it empty if the label has no such value.

  8. Download your results

    FileWhat it is
    Corrected CSVYour spreadsheet with every checked value set by your marks. This is the one to use. It also has .parse1, .parse2 and .source columns so you can see where each value came from.
    Comparison CSVOne row per label and column: both readings, the verdict, the third reading, whether it held, your mark and the model.
    Parse 2 CSV and Parse 3 CSVThe second and third readings on their own.
    Manual checks summaryFor each column, how often the first reading was right or wrong. Unsure is counted separately.
    Raw responsesEvery reply from the AI, with the settings and instructions used.
    Run infoAgreement and flip rates per column, token counts, settings and prompts, for a methods section.
Getting an error rate you can report

Checking every label is rarely practical. Choose a random sample of labels in step 3 and check those. The manual checks summary then tells you how often the first reading was right, for that sample.

If something goes wrong

I get "rate limit" errors

Too many pictures are being sent at once. Lower Requests at once. If it keeps happening, check the limits on your AI account.

Some labels failed

Use Re-transcribe and choose Failed (step 1), or Retry failed (step 3). A label also counts as failed if the reply was not in the expected format. Check your instructions if many fail.

I closed the page in the middle of a run

Finished readings are kept in your browser. Open the same file in the same browser and carry on. If you used the half-price batch option, the job keeps running and you can fetch the results later.

The page does not remember my work

Work is stored in the browser you used. A private window, another browser, or clearing your browsing data starts you from nothing. Save your files as you go.

The transcription misses faint or small writing

In step 1, try a larger upscale factor or autocontrast, and set Image detail to high. Test on a few labels before you run everything.

The columns in step 3 look wrong

Check the column roles you assigned. The picture name column has to match the file names in your folder of pictures. Columns to check come from the Tags column, so it needs to be there.
